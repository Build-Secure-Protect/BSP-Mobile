The Mobile Core: three screen layouts

Set A of the mock-ups, part 2. Right-clicking the Mobile Core opens this screen (teal: a player's screen). It must do four things: show what the core will take (the gather from D3, counted against the allowance of the tier from D4), name the blocks it refuses (bedrock, another core, admin blocks, Anti Totem blocks), assemble and release the construct, and buy the next tier in Shatter Coins. The helm lock (D5) and flight plans (D12) come later and are shown as closed tabs or greyed keys so the layout already has room for them. Three states: not assembled (the gather has counted the blocks), parked, moving (the screen still opens but releasing is refused). 1.5x the in-game size; the panel is 320 x 200 GUI pixels, which fits the smallest window the rules name.

Layout A: the gauge

One big ring in the middle: the blocks the gather counted against the allowance, with the tier under it. The construct's name above, the state as a chip. The refused blocks are one line under the ring, in red, with the count. Keys in two groups with a gap: ASSEMBLE or RELEASE on the left, UPGRADE on the right. The simplest screen; the block list lives behind the BLOCKS key as a second page.

Layout B: the ledger

Two columns. Left, the construct's card: its name, the tier as five pips, the allowance as a bar, the state, and the keys under it. Right, the ledger: one row per kind of block the gather counted, with its count, the refused kinds in red at the top so the player sees at once what holds the assembly back. Scrolls when a build has many kinds. The screen that tells the most; the one a builder with a big base will want.

Layout C: tabs

BSP-Core's shape: tabs along the top, CORE, BLOCKS, UPGRADE, HELM, PLAN (the last two closed until their tasks). CORE is the summary with the keys; BLOCKS the ledger; UPGRADE shows the whole tier ladder with every price, the current tier marked, and BUY on the next one. The same screen later takes the helm lock and the flight plan as tabs without moving anything. Shown: the CORE tab and the UPGRADE tab.

Decisions for this set (defaults first)

  1. The screen layout. Default: Layout C, tabs, because the helm lock and flight plans slot in as tabs later. Or Layout B, the ledger, with its full block list always in view. Or Layout A, the gauge, the simplest.
  2. The outline in the world. Default: while the screen is open, the blocks the core will take are outlined in teal and the refused ones in red, drawn like BSP-Core's zone boxes. Or no outline; the list on the screen is enough.
  3. Naming. Default: a construct has a name the owner types on this screen, shown in admin lists and on the helm later; new cores start as "Construct" followed by a number. Or no names, constructs are known by their owner and position.
  4. Release. Default: RELEASE puts the blocks back into the world at the nearest 90 degrees, only while parked; a second click within three seconds confirms. Or release is allowed while moving, dropping the construct where it is.
